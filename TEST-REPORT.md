# Журнал тестування TravelGuide

## Виправлені дефекти

| № | Що було | Причина | Виправлення |
|---|---|---|---|
| 1 | Початкові JPEG займали 634 973 байти, а LCP становив 4,5 с. | Повнорозмірні файли завантажувалися без формату WebP; зображення нижче першого екрана не відкладалися. | Створено WebP-версії потрібних розмірів, додано lazy loading, розміри зображень та пріоритет головного фото. Загальний розмір зменшено до 210 606 байтів. |
| 2 | Заголовок «Місцеві провідники» мав рівень h3 одразу після секційного h2. | Для секції пропущено рівень заголовка. | Заголовок секції змінено на h2, назви карток залишено на рівні h3. |
| 3 | Email `denys@` проходив власну перевірку форми. | Перевірявся лише наявний символ `@`. | Перевірка використовує `validity.valid` поля типу email; помилковий ввід позначається `aria-invalid`. |
| 4 | Браузер отримував 404 для `/favicon.ico`. | Файл іконки не був підключений. | Додано `favicon.svg` і посилання на нього в документі; повторна відповідь — HTTP 200. |

## Тест-кейси

| № | Перевірка | Очікуваний результат | Результат |
|---|---|---|---|
| 1 | Перехід усіма сімома пунктами навігації | Кожне посилання відкриває відповідну секцію | Пройшов |
| 2 | Перемикач світлої та темної теми | Кольори й доступні назви кнопки змінюються | Пройшов |
| 3 | Надсилання порожньої форми | Відображається помилка; дані не надсилаються | Пройшов |
| 4 | Надсилання з email `denys@` | Відображається помилка; POST не виконується | Пройшов |
| 5 | Надсилання коректної форми | Відповідь HTTP 201 відображається як успіх | Пройшов |
| 6 | Завантаження новин | GET повертає три записи, які з’являються на сторінці | Пройшов |
| 7 | Зображення, alt і підписи форми | WebP завантажуються; задані розміри, alt і label | Пройшов |
| 8 | Телефон, 390 px | Одна колонка, немає горизонтального переповнення | Пройшов |
| 9 | Планшет і ноутбук, 768 та 1440 px | Дві й три колонки відповідно; переповнення немає | Пройшов |
| 10 | Клавіатура, Console, Network, інший браузер | Видимий фокус; немає помилок консолі та HTTP 4xx/5xx; сторінка працює в Chrome й Edge | Пройшов |

Позитивний запит форми в автоматизованому тесті повертав контрольовану тестову відповідь, щоб перевірити обробку форми без надсилання реальних даних. GET новин перевірено також із реальним мережевим запитом.

## Повторний Lighthouse

| Категорія / метрика | До змін | Після змін |
|---|---:|---:|
| Performance | 84/100 | 99/100 |
| LCP | 4,5 с | 2,1 с |
| CLS | 0 | 0 |
| Total Blocking Time | 0 мс | 0 мс |
| SEO | 100/100 | 100/100 |
| Accessibility | 100/100 | 100/100 |

Під час перевірки реального Network головна сторінка, стилі, скрипт, WebP-зображення, favicon і GET новин повернули HTTP 200. Помилок Console та JavaScript не виявлено. У Chrome 157 і Edge 157 перевірено форми, навігацію, тему, зображення й адаптивні розміри.

Контрастність виміряна для обох тем: мінімальне перевірене співвідношення — 5,68:1 у світлій та 8,44:1 у темній темі. Шрифт Arial завантажується із системного стеку, зовнішніх вебшрифтів немає; `font-display` для `@font-face` не застосовується. Скрипт `script.js` уже підключено з `defer`, а невикористаних скриптів не виявлено.

Решта рекомендацій Lighthouse стосується кеш-заголовків локального сервера та блокування CSS. Аудит виконано через локальний сервер розробки без production-конфігурації кешування.
